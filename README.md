# 카페 읽음 표시 (naver-cafe-checker)

네이버 카페는 글을 읽고 목록으로 돌아와도 어떤 글을 읽었는지 표시해 주지 않습니다. 이 확장 프로그램은 읽은 글을 기억해 두었다가 글 목록에서 제목을 흐리게 하고 앞에 **읽음** 배지를 붙입니다.

Chrome / Edge / Whale 등 Chromium 기반 PC 브라우저(Chrome 111 이상)용이며 Manifest V3로 만들었습니다.

## 설치

1. [Releases](https://github.com/ljhoo24/naver-cafe-checker/releases/latest)에서 `naver-cafe-checker-v<버전>.zip`을 내려받습니다.
2. 계속 보관할 폴더(예: `문서\확장프로그램\naver-cafe-checker`)에 압축을 풉니다. 압축을 풀면 `extension` 폴더와 `README.md`가 나옵니다.
3. 주소창에 `chrome://extensions`를 입력합니다 (Edge는 `edge://extensions`, Whale은 `whale://extensions`).
4. 오른쪽 위 **개발자 모드**를 켭니다.
5. **압축해제된 확장 프로그램을 로드합니다**를 누르고, 압축을 푼 폴더 안의 **`extension`** 폴더(`manifest.json`이 들어 있는 폴더)를 선택합니다.
6. 툴바의 퍼즐 아이콘에서 **카페 읽음 표시**를 고정하면 설정 창을 바로 열 수 있습니다.
7. 이미 열려 있던 네이버 카페 탭은 한 번 새로고침합니다.

주의:

- 압축을 푼 폴더를 지우거나 옮기면 확장 프로그램이 동작하지 않습니다. 옮기면 다른 확장 프로그램으로 인식되어 이 브라우저의 읽음 기록도 새로 시작됩니다 (Google 계정 동기화를 켜 두었다면 공유된 최근 기록은 다시 받아옵니다).
- Chrome이 시작할 때 "개발자 모드 확장 프로그램 사용 중지" 안내를 띄울 수 있습니다. 이 확장 프로그램은 웹 스토어가 아닌 직접 설치 방식이라 나오는 안내이며, 닫으면 계속 사용할 수 있습니다.
- 소스에서 직접 설치할 때는 저장소를 `git clone`한 뒤 같은 방법으로 `extension` 폴더를 선택합니다.

### 업데이트

1. 새 버전 ZIP을 내려받아 **처음 설치한 폴더에 덮어쓰기**로 압축을 풉니다 (폴더 위치를 바꾸지 않아야 기록이 유지됩니다).
2. `chrome://extensions`에서 **카페 읽음 표시**의 새로고침(↻) 버튼을 누릅니다.
3. 열려 있는 카페 탭을 새로고침합니다.

### v1.2.0 변경 사항 (미배포, 테스트 중)

- 오래 열어둔 글에서 좋아요가 실패하면 자동으로 새로고침한 뒤 좋아요를 다시 누릅니다 (아래 **좋아요 자동 재시도** 참고).
- 최소 Chrome 버전이 111로 올라갑니다 (페이지 알림 창을 가로채는 데 필요).

### v1.1.0 변경 사항

- 글 본문 화면에서 좋아요·댓글·공유·신고·정렬·작성자 버튼 등에 `읽음` 배지가 붙던 문제를 수정했습니다. 이 버튼들은 `#`이나 지금 보고 있는 글 주소를 링크로 쓰기 때문에 읽은 글 링크로 잘못 인식됐습니다. 이제 `#`·`javascript:` 링크와 현재 열린 글 자신을 가리키는 링크는 표시하지 않습니다. 본문 아래 게시판 목록의 다른 글은 그대로 표시됩니다.
- Google 계정 동기화를 추가했습니다 (아래 참고). 권한에 `alarms`가 추가됩니다.

## 사용법

- 카페 글을 열면 자동으로 읽음 기록이 남습니다. 목록에서 제목을 클릭(가운데 클릭·Ctrl+클릭으로 새 탭 열기 포함)해도 바로 기록됩니다.
- 목록으로 돌아오면 읽은 글의 제목이 회색으로 바뀌고 앞에 `읽음` 배지가 붙습니다. 같은 행의 댓글 수 링크는 흐리게만, 앨범형 썸네일은 반투명하게 표시합니다.
- 여러 탭·카페 내부 프레임에 동시에 반영됩니다. 글 하단의 게시판 목록, 모바일 웹, 카페 홈(section.cafe.naver.com)의 글 링크에도 적용됩니다.
- **되돌리기:** 글 링크 위에서 우클릭 → **카페 읽음 표시: 안 읽은 글로 되돌리기**. 반대로 **읽은 글로 표시**도 있습니다.
- **툴바 버튼:** 전체 사용 여부, 흐리게/배지 표시 방식, 좋아요 자동 재시도, Google 계정 동기화, 기록 개수 확인, 기록 전체 삭제(두 번 눌러 확인).

## 좋아요 자동 재시도

네이버 카페 글을 오래 열어 두었다가 좋아요(하트)를 누르면, 페이지를 열 때 받은 좋아요 인증 정보가 만료되어 "새로고침 후 다시 시도" 류의 알림이 뜨고 좋아요가 되지 않습니다. 이 기능은 그 과정을 대신합니다.

1. 좋아요를 누른 직후 뜬 알림이 만료 안내(`새로고침`, `오래`, `만료`, `시간이 지나` 등의 문구)이면 알림을 띄우지 않고 페이지를 새로고침합니다.
2. 새로고침 후 같은 글의 좋아요 버튼이 준비되면 한 번 눌러 주고, 버튼 아래에 안내를 잠깐 표시합니다. 이미 좋아요가 눌려 있으면 누르지 않습니다 (실수로 취소되지 않도록).
3. 자동으로 누른 뒤에도 다시 실패하면 반복하지 않고 원래 알림을 그대로 보여 줍니다.

- 본인 글·권한 부족·네트워크 오류 등 다른 이유의 알림은 그대로 표시됩니다. 댓글 좋아요, 좋아요 수(누른 멤버 목록) 클릭에는 동작하지 않습니다.
- 설정 창의 **좋아요** 항목에서 끌 수 있습니다. 설정 창에는 좋아요 직후 뜬 마지막 알림 문구와 자동 처리 여부가 표시됩니다. 만료 알림인데 "처리 안 함"으로 나오면 그 문구를 알려 주세요. 문구 인식 규칙(`extension/like-hook.js`의 `EXPIRED`)에 추가하겠습니다.
- 구현: 네이버 좋아요 모듈(`cafe.like.naver.com` reaction 플러그인)은 실패를 `window.alert`로 알리므로, 페이지 쪽(MAIN world)에서 실행되는 `like-hook.js`가 좋아요 클릭 직후의 알림만 확인합니다. 새로고침 후 다시 누르는 작업은 `like.js`가 합니다. 다시 누를 글은 탭의 `sessionStorage`에 2분간만 보관합니다.

## Google 계정 동기화

같은 Google 계정으로 로그인한 Chrome끼리 읽음 기록을 공유합니다. 기본으로 켜져 있고 설정 창에서 끌 수 있습니다.

- **조건:** Chrome에 Google 계정으로 로그인하고 동기화를 켠 상태에서, 동기화 항목의 **확장 프로그램**이 켜져 있어야 합니다 (`chrome://settings/syncSetup`). 조건이 안 되면 이 브라우저에만 저장됩니다. 각 기기에 확장 프로그램이 설치되어 있어야 합니다.
- **방식:** Chrome이 제공하는 `chrome.storage.sync`를 사용합니다. 별도 서버나 네이버 계정 연동은 없습니다.
- **용량:** Chrome이 확장 프로그램 하나에 허용하는 동기화 용량은 100KB입니다. 글 번호를 카페별로 압축해 **최근 읽은 글부터 약 2만~4만 개**를 공유합니다 (카페 수·글 번호 분포에 따라 다름). 전체 기록(최대 5만 개)은 각 기기에 그대로 남습니다.
- **반영 시점:** 쓰기 횟수 제한 때문에 변경 사항은 약 1분 단위로 모아서 올리고, 15분마다 한 번 더 확인합니다. 설정 창의 **지금 동기화**로 바로 실행할 수 있습니다.
- **되돌리기·삭제:** 우클릭 **안 읽은 글로 되돌리기**와 **읽음 기록 전체 삭제**도 다른 기기에 전달됩니다. 되돌린 뒤 다시 읽으면 다시 읽음으로 표시됩니다.
- 기기 간 시계 차이가 크면 삭제 전파 순서가 어긋날 수 있습니다.

## 동작 방식

- 글 주소에서 카페 ID와 글 번호를 읽어 기록합니다. 인식하는 주소 형식:
  - PC 신형: `cafe.naver.com/f-e/cafes/{카페ID}/articles/{글번호}` (`/ca-fe/cafes/...` 포함)
  - 모바일: `m.cafe.naver.com/ca-fe/web/cafes/{카페ID}/articles/{글번호}`
  - 구형: `ArticleRead.nhn?clubid=...&articleid=...`, 상단 주소의 `iframe_url` 파라미터
  - 짧은 주소: `cafe.naver.com/{카페주소}/{글번호}`
- 짧은 주소는 카페 ID 대신 카페 이름을 쓰므로, 카페 페이지를 열 때 `카페주소 → 카페 ID` 대응을 자동으로 학습해 두 형식을 같은 글로 취급합니다. 학습 전에 짧은 주소로 읽은 글도 나중에 연결됩니다.
- 사이트의 요소에 `data-ncc-read` 속성만 붙이고 표시는 CSS로 합니다. 네이버 화면에 새 요소를 끼워 넣지 않으므로 사이트 동작을 방해하지 않습니다. 페이지 이동·추가 로딩으로 바뀐 목록도 자동으로 다시 표시합니다.
- 기록은 최대 50,000개까지 보관하고 넘으면 오래된 것부터 지웁니다.

## 한계

- 네이버 앱·모바일 앱과는 연동되지 않으며, 확장 프로그램 설치 전에 읽은 글은 표시되지 않습니다.
- 글 목록 항목이 링크(`<a href>`)가 아닌 스크립트 클릭으로만 열리는 화면에서는 목록 표시가 되지 않을 수 있습니다. 글을 열면 기록은 남습니다.
- 네이버가 주소 형식을 바꾸면 `extension/core.js`의 `parseArticle` 보완이 필요합니다.

## 저장과 권한

기록과 설정은 `chrome.storage.local`에 저장되며, 동기화를 켜면 최근 기록의 압축본이 `chrome.storage.sync`(Chrome 계정 동기화)에 저장됩니다. 그 외 외부 서버로 전송하지 않습니다. 분석 도구, 네이버 로그인·API 접근은 없습니다.

- `storage`: 읽음 기록·설정 저장
- `contextMenus`: 링크 우클릭 메뉴
- `alarms`: 동기화를 1분·15분 단위로 모아서 실행
- 콘텐츠 스크립트 실행 범위: `cafe.naver.com`, `m.cafe.naver.com`, `section.cafe.naver.com`

## 검증

- 자동 테스트(jsdom): 주소 형식 파싱, 목록 표시(행당 배지 1개·댓글 수·썸네일), 글 본문 버튼 제외, 클릭/글 열기 기록, SPA 페이지 이동 감지, 동적 목록 추가·링크 변경, 카페주소↔ID 학습, 설정 변경, 기록 삭제, 우클릭 메뉴, 오래된 기록 정리, 설정 창.
- 좋아요 테스트: 네이버 좋아요 모듈의 동작(버튼 선반영 → 실패 시 되돌림 + 알림)을 흉내 낸 페이지에서 만료 알림 숨김·새로고침, 새로고침 후 버튼 준비 대기·1회 클릭, 재실패 시 반복 없음, 이미 눌린 경우 건너뜀, 다른 알림 유지, 설정 끄기, 본문 없는 프레임에서 대기. 실제 만료 상황(서버 응답 문구)에서는 아직 확인하지 않았습니다.
- 동기화 테스트: 두 브라우저가 한 계정 저장소를 공유하는 상황에서 기록 합치기, 되돌리기·전체 삭제 전파, 변경 없을 때 쓰기 생략, 5만 개 기록에서 Chrome 용량 제한(항목당 8KB·전체 100KB) 준수, 쓰기 한도 오류 표시. 실제 두 기기 간 Chrome 동기화는 확인하지 않았습니다.
- 네이버 공개 배포 코드(PC `ca-fe.pstatic.net/pc/_next`, 모바일 `ca-fe.pstatic.net/web-mobile`)와 공개 카페 HTML에서 글 주소 형식과 목록 클래스(`.article-board .board-list a.article` 등)를 확인했습니다.
- 목록 표시 스타일과 설정 창은 브라우저에서 렌더링을 확인했습니다. 로그인한 실제 카페 화면에서의 확인은 설치 후 직접 해 보시고, 표시되지 않는 화면이 있으면 해당 주소를 알려 주세요.
