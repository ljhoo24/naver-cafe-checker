# 읽은 글 새 댓글 표시 (`+N`) 설계

- 날짜: 2026-10-18
- 대상 버전: 2.4.0
- 상태: 설계 승인, 구현 전

## 목적

읽은 글은 목록에서 회색으로 흐려지므로, 읽은 뒤에 새 댓글이 달려도 알아차릴 방법이 없다. 읽은 글의 댓글 수가 읽었을 때보다 늘었으면 목록의 댓글 수 옆에 `+N`을 표시한다.

```text
[읽음] 오늘 모임 후기 (회색)   [5] +3
                                  ^^ 초록, 굵게
```

## 용어

- **목록 댓글 수**: PC 게시판 목록 행의 댓글 수 링크(`a.cmt`, 텍스트 `[5]`) 값.
- **글 화면 댓글 수**: 글 화면 상단의 `댓글 N` 값.
- **기준 댓글 수**: 내가 마지막으로 그 글을 봤을 때의 댓글 수. `+N` = 목록 댓글 수 − 기준 댓글 수.

## 범위

포함:

- PC 게시판 목록형 보기에서 읽은 글의 `[N]` 댓글 수 링크.
- 기준 댓글 수를 목록 클릭과 글 화면 양쪽에서 기록.
- 설정 창의 켜기/끄기.

제외:

- 앨범형·카드형 보기, 모바일 웹, 카페 홈처럼 댓글 수가 `[N]` 형식 링크가 아닌 화면. 지금의 `kind()` 판정이 `'extra'`이면 동작은 하지만 확인하지 않는다.
- 기준 댓글 수의 Google 동기화.
- 새 댓글이 있는 글로 이동하는 단축키, 알림.

## 저장

`chrome.storage.local`에 새 접두사 `k:`를 쓴다.

```text
k:c:<cafeId>:<articleId>  -> number   기준 댓글 수 (카페 숫자 ID로 기록된 글)
k:u:<cafeUrl>:<articleId> -> number   기준 댓글 수 (카페 주소 이름으로만 기록된 글)
```

- 키는 읽음 키에서 `r:`를 `k:`로 바꾼 것이다. 읽음 키와 1:1로 대응한다.
  - `lookupKeys` 가운데 실제로 `reads`에 있는 키를 바꿔 쓴다. 기준은 읽은 글에만 둔다. 클릭·글 화면에서는 `markRead`가 먼저 실행되므로 그 시점에 읽음 키가 있다.
- 기준 댓글 수는 이 브라우저에만 둔다. `sync.js`는 바꾸지 않는다. 다른 기기에서 읽은 글은 이 기기 목록에 처음 보일 때 기준이 생긴다.
- 값은 0 이상의 정수. 그 외 값은 기준 없음으로 본다.
- 용량: 읽음 기록 최대 5만 개에 대응해 최대 5만 개, 약 1.5MB. `storage.local` 기본 한도 10MB 안이다.

### 정리

- `background.js`의 `storage.onChanged`에서 `r:X`가 지워지면 `k:X`도 지운다. 안 읽은 글로 되돌리기, 전체 삭제, 동기화로 넘어온 삭제가 모두 여기로 모인다.
- `prune()`은 오래된 읽음 기록을 지울 때, 대응하는 읽음 키가 없는 `k:` 키(놓친 이벤트로 남은 것)도 함께 지운다.

## 기준 기록 (`content.js`)

`content.js`가 `k:` 값을 `Map`(`bases`)으로 들고 있고, `storage.onChanged`로 다른 탭·프레임 변경을 반영한다. 저장은 값이 바뀔 때만 한다.

| 시점 | 동작 |
|---|---|
| 목록에서 글 제목 또는 `[N]` 링크 클릭 (`click`, 가운데 클릭 포함) | 같은 행(`ROW`)의 댓글 수 링크 값을 기준으로 저장 |
| 글 화면을 보는 동안 (`currentArticle`이 있을 때 scan마다) | 글 화면 댓글 수를 기준으로 저장. 내가 단 댓글도 곧바로 기준에 들어가 `+1`로 뜨지 않는다 |
| 목록에 읽은 글이 보이는데 기준이 없음 | 지금 목록 댓글 수를 조용히 기준으로 저장. 이번에는 `+N` 없음 |
| 목록 댓글 수 ≤ 기준 | 아무것도 하지 않음. 기준을 낮추지 않는다 |

- 기준을 낮추지 않는 이유: 다른 탭에 갱신 안 된 목록이 떠 있으면 그 탭의 옛 댓글 수가 글 화면에서 막 올린 기준을 낮추고, 나중에 가짜 `+N`이 생긴다. 대신 댓글이 삭제된 뒤 새로 달린 댓글은 삭제된 수만큼 덜 보일 수 있다. 놓치는 쪽을 가짜 표시보다 낫다고 본다.

- 글 화면 댓글 수는 `currentArticle`이 설정된 프레임(글 주소를 가진 프레임)에서 찾는다. 찾지 못하면 아무것도 저장하지 않는다.
- 글 화면 댓글 수 위치 후보: `href`에 `commentFocus`가 들어 있고 텍스트가 `댓글 N`인 링크(테스트 fixture의 구조), 그리고 실제 카페에서 확인할 네이버 선택자. 텍스트는 `/댓글\s*([\d,]+)/`로 읽는다.
- 기능이 꺼져 있거나 확장 전체가 꺼져 있으면 기준도 기록하지 않는다.

## 표시

- scan에서 읽은 글의 링크 가운데 `kind()`가 `'extra'`이고 `parseCount`로 숫자를 읽을 수 있는 것(댓글 수 링크)을 대상으로 한다.
- 목록 댓글 수 > 기준이면 링크에 `data-ncc-cmt-new="<차이>"`를 붙이고, 아니면 뗀다.
- 설정이 켜져 있으면 `<html>`에 `data-ncc-cmt`를 붙인다. 흐리게·배지 설정과는 별개다.
- `content.css`:

```css
html[data-ncc-cmt] a[data-ncc-cmt-new]::after {
  content: "+" attr(data-ncc-cmt-new);
  margin-left: 4px;
  color: #03c75a !important;
  font-weight: 700;
}
```

- 사이트 요소에는 속성만 붙인다. 새 요소를 끼워 넣지 않는 기존 원칙과 같다.
- `[5]` 자체는 지금처럼 흐린 색으로 두고 `+3`만 진하게 표시한다.

## 설정

- `core.js` `DEFAULTS`에 `cmtNew: true` 추가.
- 설정 창 **표시 방식**에 체크박스: `읽은 글에 새 댓글 수 표시 (+3)`. `popup.js` `KEYS`에 `cmtNew` 추가.

## 코드 변경 위치

| 파일 | 변경 |
|---|---|
| `core.js` | `COMMENTS = 'k:'`, `commentKey(readKey)`, `parseCount(text)`, `DEFAULTS.cmtNew`, 저장 구조 주석 |
| `content.js` | `bases` 관리, 클릭·글 화면·목록 기준 기록, scan에서 `data-ncc-cmt-new` 부여, `data-ncc-cmt` 루트 플래그 |
| `background.js` | `r:` 삭제 시 `k:` 삭제, `prune()`에서 짝 없는 `k:` 삭제 |
| `content.css` | `+N` 스타일 |
| `popup.html`, `popup.js` | 설정 체크박스 |
| `README.md` | 기능 설명, 변경 사항, 저장 구조 |

## 테스트 (jsdom)

- `core`: `parseCount`(`[5]`, `(1,234)`, `댓글 7`, 숫자 아님), `commentKey`, `cmtNew` 기본값.
- `content`:
  - 목록 클릭 시 같은 행의 댓글 수가 기준으로 저장됨.
  - 기준보다 목록 댓글 수가 크면 `data-ncc-cmt-new`가 붙고 차이 값이 맞음.
  - 글을 다시 열면 기준이 갱신되어 `+N`이 사라짐.
  - 글 화면에서 `댓글 N`이 늘면(내 댓글) 기준이 따라감.
  - 기준이 없는 읽은 글은 배지 없이 기준만 저장됨.
  - 목록 댓글 수가 기준보다 작으면 배지 없이 기준 유지.
  - 안 읽은 글에는 붙지 않음.
  - 설정을 끄면 루트 플래그가 빠지고 기준을 기록하지 않음.
- `background`: `r:` 삭제 시 `k:` 삭제, `prune()`의 짝 없는 `k:` 삭제.
- `popup`: 체크박스 저장.

## 실제 카페에서 확인할 것

1. 글 화면 `댓글 N`의 실제 DOM 위치와 선택자.
2. 글 화면 댓글 수와 목록 `[N]`이 같은 방식으로 집계되는지(답글 포함 여부, 삭제된 댓글 처리). 다르면 글 화면 기록을 빼고 목록 기록만 쓴다. 이 경우 단축키로 넘긴 글은 다음 목록 표시 때 기준이 생기고, 내가 단 댓글은 `+1`로 보인다.

### 확인 결과 (2026-10-18)

- 목록 댓글 수는 `<a class="cmt"><span class="blind">댓글수</span>[7]</a>`로, 텍스트가 `댓글수[7]`이다. `parseCount`와 `kind()`가 이 형식을 읽도록 고쳤다.
- 글 본문은 `cafe_main` iframe(`/ca-fe/cafes/<id>/articles/<n>`)에 있고, 댓글 수는 `a.button_comment`의 `댓글 2`다(상단 `.ArticleTool`, 하단 `.box_left` 두 곳). 같은 프레임 아래쪽 다른 글 목록에도 `댓글 [N]`이 있어서, `.button_comment`를 먼저 보고 다른 글을 가리키는 링크 안의 숫자는 건너뛴다.
- 답글이 있는 글에서도 목록과 글 화면 댓글 수가 같았다. 글 화면 기록을 유지한다.
- 댓글이 삭제된 경우는 확인하지 않았다.
